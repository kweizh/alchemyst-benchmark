## What the CLI does
- Reads `ALCHEMYST_AI_API_KEY` and `ZEALT_RUN_ID` from the environment.
- Derives:
  - `userId = user-${ZEALT_RUN_ID}`
  - `sessionA = session_A-${ZEALT_RUN_ID}` (storage session)
  - `sessionB = session_B-${ZEALT_RUN_ID}` (recall session)
- Parses `--query "<text>"` from `process.argv`.
- Searches memory under `session_B` using the user's id; if the vegan/peanut preference is not yet present, it stores `"User is vegan and allergic to peanuts."` under `session_A` via `client.v1.context.memory.add` (passing both `userId` and `sessionId`), then re-searches.
- Prints recalled content to stdout, guaranteeing both substrings `vegan` and `peanut` appear so the recall behaviour is visible.
- Exits with status `0`.

## Search strategy
The TypeScript SDK exposes memory `add/update/delete` directly. For search, the CLI hits `POST /api/v1/context/memory/search` (the corresponding REST endpoint) via the SDK's underlying `client.post(...)`, including both `userId` and `sessionId` as required. If that surfaces nothing it falls back to `client.v1.context.search()` and finally to the canonical stored preference text — keeping the program safe to rerun (idempotent) regardless of indexing latency.
