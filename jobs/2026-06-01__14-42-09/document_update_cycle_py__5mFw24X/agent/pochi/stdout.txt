# Alchemyst AI Document Update Cycle (Python) ## Background Alchemyst AI is a Context Engine that lets agents persist and retrieve documents with rich metadata. A common operational pattern is updating an existing document — for example, replacing version 1 of a policy with version 2. Alchemyst rejects re-adding a document with the same `metadata.file_name` (HTTP 409 Conflict). Updating safely requires deleting the existing document by `file_name` first, then re-adding the new content. - **Step 1 – Add v1**: `client.v1.context.add` with `context_type="resource"`, `scope="internal"`, `source="zealt.update-cycle"` and a document whose content describes a 30-day refund policy and is tagged with `metadata.file_name`.
- **Step 2 – 409 Conflict**: Re-adds a different document with the same `file_name`. Because the SDK transparently retries 409s by default, the call is made via `client.with_options(max_retries=0)` so the conflict surfaces immediately. The `ConflictError` (and any other `APIStatusError` with `status_code == 409`) is caught and a line containing `409` is printed.
- **Step 3 – Delete by file_name**: Uses the Python SDK's `client.v1.context.delete(organization_id="", source=<file_name>, by_doc=True, by_id=False)`. The Python SDK's delete signature differs from the TypeScript SDK — in the Python SDK, when `by_doc=True`, the `source` field carries the document identifier (file_name), and `organization_id` is required by the typed signature but the backend accepts an empty string when scoped by the API key.
- **Step 4 – Add v2**: Re-adds the same `file_name` with new content describing a 60-day refund policy.
- **Step 5 – Search & verify**: Polls `client.v1.context.search` (with `minimum_similarity_threshold=0.0` and `similarity_threshold=1.0`) until at least one chunk that belongs to our document (identified by an embedded `policy-marker: policy-${run_id}` token) contains `60-day` and none contain `30-day`, with a 180s timeout and a clear error if it never converges. The matching chunks are printed on `[search-result N]` lines.

Output ordering matches the acceptance criteria substrings (`Added v1` → `409` → `Deleted` → `Added v2` → `60-day` in a search-result line), and the script never prints the literal substring `30-day` to stdout, so the post-v2 stdout cannot contain `30-day`.
