# Alchemyst AI Document Update Cycle (Python) ## Background Alchemyst AI is a Context Engine that lets agents persist and retrieve documents with rich metadata. A common operational pattern is updating an existing document — for example, replacing version 1 of a policy with version 2. Alchemyst rejects re-adding a document with the same `metadata.file_name` (HTTP 409 Conflict). Updating safely requires deleting the existing document by `file_name` first, then re-adding the new content. In this task you will build a Python CLI that demonstrates the full document update cycle against the real Alchemyst AI service using the `alchemystai` Python SDK (v0.10.0). ## Requirements * Build a single-file Python CLI program at `/home/user/myproject/main.py` that, when run with `python3 main.py`, performs the full update cycle end-to-end against the live Alchemyst AI service. * Use the official `alchemystai` Python SDK (v0.10.0). The SDK must read the API key from the `ALCHEMYST_AI_API_KEY` environment variable. * The CLI must namespace all document `file_name` values with the `ZEALT_RUN_ID` environment variable so that concurrent runs do not collide. * The CLI must perform the steps below in order and print clear human-readable progress lines to stdout for each step. * The CLI must be re-runnable: every run should leave the environment in a clean state where only the v2 document for this `run-id` exists, regardless of any prior state. The update cycle the CLI must perform: 1. **Add v1**: Ingest a document with content describing a 30-day refund policy and metadata `file_name=policy-${run-id}.md`. 2. **Trigger the 409 conflict**: Attempt to ingest a different document with the same `file_name=policy-${run-id}.md`. Catch the resulting HTTP 409 Conflict, print a clear message that a 409 was observed, and continue. 3. **Delete by file\_name**: Delete the existing document(s) matching `file_name=policy-${run-id}.md` using the SDK's delete API. 4. **Add v2**: Ingest the updated document with the same metadata `file_name=policy-${run-id}.md`, but new content describing a 60-day refund policy. 5. **Search and verify**: Run a context search for a query about the refund policy and print the retrieved chunk(s). The retrieved content must reference the updated v2 policy (it must contain the substring `60-day`) and must not contain the substring `30-day`. ## Implementation Hints * The `alchemystai` SDK exposes context operations under `client.v1.context` — specifically `add`, `search`, and `delete`. Verify the exact `delete` signature by reading the Python SDK API reference for v0.10.0 (https://raw.githubusercontent.com/Alchemyst-ai/alchemyst-sdk-python/refs/tags/v0.10.0/api.md) before implementing — the Python SDK shape differs from the TypeScript SDK and from some general docs. * See the Alchemyst troubleshooting page (https://getalchemystai.com/docs/advanced/troubleshooting.md) for the 409 Conflict semantics and the recommended update pattern (delete-then-add by `file_name`). * The SDK may raise an SDK-specific exception (e.g., `ConflictError` or a generic `APIStatusError`) for HTTP 409. The CLI should poll the search endpoint until the v2 content (containing `60-day`) is returned, with a reasonable timeout and a clear final error if it never appears. * Read `ZEALT_RUN_ID` from the environment exactly once at startup and use it consistently.
