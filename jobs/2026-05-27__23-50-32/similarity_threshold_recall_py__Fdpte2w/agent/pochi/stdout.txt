# Demonstrate `similarity_threshold` Sensitivity with the Alchemyst AI Python SDK ## Background Alchemyst AI is a Context Engine that ingests documents and retrieves relevant chunks based on semantic similarity. The `v1.context.search` API accepts a `similarity_threshold` parameter (typically between 0.0 and 1.0) that controls how strict the retrieval is: low values increase recall (return more, possibly loosely related chunks), while high values increase precision (return only very strong matches). In this task, you will use the Python SDK `alchemystai` to ingest a small corpus that contains both directly relevant and loosely related documents about a specific topic. You will then issue two searches against the same query with different `similarity_threshold` values (`0.5` and `0.9`) and persist the count of returned context chunks for each search to a JSON report file. ## Requirements * Use the official Python SDK package `alchemystai` (import path: `alchemyst_ai`). * Read the API key from the `ALCHEMYST_AI_API_KEY` environment variable. * Read the current run identifier from the `ZEALT_RUN_ID` environment variable. Use it to make every ingested document's `file_name` metadata unique per run (e.g. `<base-name>-${ZEALT_RUN_ID}.md`) so the task is safe to run concurrently and is retryable against the shared Alchemyst tenant. * Ingest at least five documents into the Alchemyst context engine using `client.v1.context.add`: * At least two documents whose content is directly about the query topic (the company's refund / money-back policy). * At least three documents whose content is on loosely related topics (e.g. shipping, privacy, returns of damaged items, general customer support). * Each ingested document MUST set `metadata.file_name` to a unique value that includes the run id. * Use `context_type="resource"`, `source="docs"`, and `scope="internal"` for ingestion. * After ingestion, perform two searches with `client.v1.context.search` using the SAME query string `"What is the refund policy?"` and `scope="internal"`: * First search: `similarity_threshold=0.5`. * Second search: `similarity_threshold=0.9`. * Write the result counts to `/workspace/threshold_report.json` with the exact schema described in the Acceptance Criteria. ## Implementation Hints * Instantiate the client with `AlchemystAI(api_key=os.environ["ALCHEMYST_AI_API_KEY"])`. * The search response object exposes a `contexts` list; count its length for each threshold. * Because Alchemyst rejects duplicate `file_name`s with HTTP 409, derive file names from the run id to keep them unique on every run. * After ingestion, you may need to give the index a brief moment before searching. * Ensure the script exits with a non-zero status if any API call fails so problems are surfaced clearly. ## Acceptance Criteria * Project path: /home/user/myproject * Output file: /workspace/threshold\_report.json * The output file MUST be valid JSON with exactly the following top-level shape: ```json { "query": "What is the refund policy?", "threshold_0_5_count": <non-negative integer>, "threshold_0_9_count": <non-negative integer>, "run_id": "<value of ZEALT_RUN_ID>" } ``` * `threshold_0_5_count` and `threshold_0_9_count` MUST both be non-negative integers reflecting the actual number of chunks returned by the two real Alchemyst searches (no mocking). * The relationship `threshold_0_5_count >= threshold_0_9_count` MUST hold, demonstrating that lowering `similarity_threshold` does not reduce recall. * `run_id` in the report MUST match the value of the `ZEALT_RUN_ID` environment variable at run time.
