# Threshold Sensitivity Probe with Alchemyst AI (Python) ## Background Alchemyst AI is a Context Engine that lets you ingest documents into a vector store and retrieve them with `v1.context.search`. The retrieval call accepts a `similarity_threshold` parameter that filters chunks below the given cosine-similarity score. Higher thresholds yield more precise but smaller result sets; lower thresholds yield broader recall. Your task is to build a Python CLI that empirically demonstrates this threshold-sensitivity behavior against the real Alchemyst AI service. This task uses the official Python SDK (`alchemystai`, v0.10.0). Because the Python SDK surface differs slightly from the TypeScript SDK and from the high-level docs, you **MUST** consult the Python v0.10.0 API reference (https://raw.githubusercontent.com/Alchemyst-ai/alchemyst-sdk-python/refs/tags/v0.10.0/api.md) before coding. In particular, the Python SDK exposes `client.v1.context.add` / `client.v1.context.search`; there is no `memory.search` method. ## Requirements * Build a single-file Python CLI at `/home/user/myproject/main.py` that ingests a small corpus of documents into Alchemyst AI and then probes how recall changes across multiple `similarity_threshold` values. * The corpus must contain a mix of documents: * At least 3 documents that are clearly on-topic for the probe query (closely related; they share the key concepts of the query). * At least 3 documents that are off-topic or only loosely related (e.g., unrelated business topics). * The probe query is fixed and provided by the task: `What is our company refund policy?`. * Accept one or more threshold values via the `--thresholds` CLI argument. The CLI must execute one `v1.context.search` call per threshold (the same query, varying only `similarity_threshold`) and report how many chunks each threshold returned. * Print a single JSON object to stdout mapping each threshold (as a string with one decimal place, e.g. `"0.5"`) to the integer recall count returned by Alchemyst at that threshold. * Recall must be monotonically non-increasing as the threshold increases: for any thresholds `t_low < t_high`, the recall at `t_low` must be greater than or equal to the recall at `t_high`. * The CLI must be safely re-runnable in parallel: namespace every ingested document so concurrent runs do not collide. ## Implementation Hints * Install dependencies with `pip install alchemystai`. The Alchemyst client reads `ALCHEMYST_AI_API_KEY` from the environment. * Read `ZEALT_RUN_ID` from the environment and use it to scope each document's `metadata.file_name` (e.g., suffix every file name with the run id) and `metadata.group_name` so concurrent test runs do not collide. Ingest under `scope="internal"`. * Search with the same `scope` you used for ingestion, the same query for every threshold, and only the threshold varying. Filter the search to your run's `group_name` so other runs' data does not leak into your counts. * Allow time for indexing between `add` and `search` (e.g., poll or wait a few seconds) so all documents are searchable before probing. * Use `argparse` (or equivalent) to accept `--thresholds` as a list of floats. Print the final result as a single JSON object using `json.dumps`. Do not print anything else to stdout; informational logs may go to stderr. * Verify the monotonic property locally before submitting; if not satisfied, your corpus likely lacks enough on-topic variety or your query/threshold sweep is too narrow. ## Acceptance Criteria * Project path: /home/user/myproject * Command: `python3 main.py --thresholds 0.5 0.7 0.9` * Command input argument format: `--thresholds <float> [<float> ...]` (one or more space-separated floats in the range (0, 1]). * The stdout of the command must be a single JSON object whose keys are the threshold values formatted with one decimal place (e.g. `"0.5"`, `"0.7"`, `"0.9"`) and whose values are non-negative integers representing recall counts returned by Alchemyst at that threshold. * Example stdout shape (counts are illustrative): `{"0.5": 6, "0.7": 4, "0.9": 2}` * For any two thresholds `t_low < t_high` passed in the same invocation, the recall at `t_low` must be >= the recall at `t_high`. * Documents must be ingested into the real Alchemyst AI service using the API key from `ALCHEMYST_AI_API_KEY`. No mocks, no hard-coded recall counts. * All ingested documents must have `metadata.file_name` and `metadata.group_name` values that include the `ZEALT_RUN_ID` value, so the run is isolated from concurrent runs.
