# Alchemyst AI — Document Update Cycle (TypeScript SDK) ## Background Alchemyst AI is a context engine for AI agents. It ingests documents (chunking + embeddings) and exposes a vector search API. The platform treats `metadata.file_name` as a dedup key: re-adding a document whose `file_name` already exists fails with a `409 Conflict`. The supported way to refresh content is the **Delete-Then-Add** update cycle. See https://getalchemystai.com/docs/advanced/troubleshooting and the TypeScript Quickstart at https://getalchemystai.com/docs/getting-started/quickstart. You will build a small Node.js + TypeScript CLI that exercises this full update cycle end-to-end against the real Alchemyst AI service using the official TypeScript SDK (`@alchemystai/sdk`). The CLI must compile to JavaScript and be runnable as `node dist/main.js`. ## Requirements * Create a Node.js TypeScript project at `/home/user/update-task` that depends on `@alchemystai/sdk` and compiles to a `dist/` directory. * The CLI takes no arguments and is invoked as `node dist/main.js`. A single invocation MUST exercise the full update cycle in order: 1. Add a first version of a document ("v1"). 2. Attempt to add the same `file_name` again and confirm the platform rejects the duplicate with a `409 Conflict` (catch and log this; do NOT crash). 3. Delete the existing document by `file_name`. 4. Add a second version of the document ("v2") under the same `file_name`. 5. Search the context engine for v2 and print the resulting content. * The CLI MUST be safely rerunnable with the same `ZEALT_RUN_ID`: running it twice in a row must still complete the full cycle and finish with v2 indexed. Read `run-id` from the `ZEALT_RUN_ID` environment variable, and use `policy-${run-id}.md` as the stored `metadata.file_name`. * Credentials: Read `ALCHEMYST_AI_API_KEY` from the environment.
